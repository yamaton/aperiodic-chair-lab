# 組立教材仕様のプレイヤーUXレビュー

2026-09-17。対象は[組立教材の仕様書](INTERACTIVE_ASSEMBLY_SPEC.md)。
ユーザーの依頼により、主担当の再読と二つの独立エージェントによるレビューを実施した。
**AIによる仕様レビューであり、実装の動作検証や人間のプレイヤーによる試用ではない。**

## 観点と方法

共通の優先事項は、プレイヤーが次の操作を理解できること、接着済みの群が壊れないこと、
失敗から戻れること、説明が操作を邪魔しないことである。
レビュアーにはファイルを編集させず、具体的な操作シナリオ、問題箇所、最小の修正案を求めた。
主担当が結果を比較し、仕様と受け入れ条件に修正を反映した。

| 担当 | 独立に確認した範囲 |
|---|---|
| `assembly_first_player_review` | 初見の学部生として、面・候補の選択、比較窓、最初の親までの案内、自由組立と材料上限を追跡 |
| `assembly_state_ux_review` | 接着、下書き、Undo/Redo、内部閲覧、モード切替の状態遷移と、作業消失・復帰不能の可能性を追跡 |
| 主担当 | 初回から次階層までの流れを再読。閲覧中の状態復元、集約と作業単位変更の間、材料の数え方、下書きの分岐を確認 |

初回レビュー対象の仕様書のSHA-256:

```text
ccafe113112786ff7da957d15cbd060d2c9fd730da273802235b72150649f908
```

二人の独立レビュアーはいずれも重大な破綻を報告しなかった。
一方、初回体験や作業の保持に影響する中程度の曖昧さが残っていた。
「対象物と操作物の二つ」「明示的な接着」「親子の閲覧と編集の分離」という骨格は維持した。

## 指摘と対応

行番号は修正前の仕様書を指す。対応先は改訂後の節で示す。

| 担当・位置 | 操作シナリオと問題 | 対応 |
|---|---|---|
| 初見担当、121–133行 | 面を選んだ後に「別の面」を何度も巡回し、何が変わったか分からない。24面×4回転の探索になり得る | §4.1: 合う模様の面を優先し、文字・矢印・位置の小図で候補を識別。全候補の番号順巡回を基本経路にしない。模様違いを調べる経路も残す |
| 初見担当、125・134・234–248行 | 比較窓で予想した回転と、3Dを裏側から見たときの回転が逆に感じられる | §4.1: 比較窓を基準に左／右90度を定義。カメラに依存しない向きと回転記号を指定 |
| 初見担当、65・78–82行 | 案内から外れる適合接触を確定しても「親の組立3/8」と表示され、親に近づいていると誤解する | §3.1: 逸脱中は進捗を材料使用数へ切り替え、戻り方を継続表示。Undoで復帰したら進捗を再計算。別の正しい親も認識する |
| 状態担当、318–325・193–200行。主担当も確認 | 親の内部を見たままUndoして親自体を消した後、「組立に戻る」で古い状態を復元する恐れがある | §6.4: 内部閲覧中は履歴操作を含む編集を休止。常時利用できる「組立に戻る」で復帰してから操作する |
| 状態担当、78–82・194–200行 | Undo直後に案内から自由へ切り替えると、操作物・Redoが残るか不明。Undoがモードを戻す実装も成立する | §3.1・4.3: モードは履歴外の設定とし、下書き・材料・視点・履歴を保持。新しい案内は再開始確認を経て開始し、取消時は完全に保持 |
| 主担当、198–200行 | Undo後の下書き変更を戻した後、Redoが新しい姿勢か古い接着か曖昧 | §4.3: 姿勢Pで接着→Undo→姿勢Qへ変更→Undo→Redoの具体例を追加。旧接着のRedoは分岐で破棄される |
| 主担当、269–272・295–310行 | 操作物を出したときの残数、親として集約してから次階層へ進むまでの追加操作が未定義 | §6.1・6.3: 接着済み／調整中／未使用を分けて集計。集約後は観察段階とし、次階層への移行時に親1個＋未使用7個へ一括変更 |
| 初見担当の再確認、改訂後§4.1・4.3 | 取り付け面Xと別の面Yを比較窓で説明中に、「この図で左へ90°」の軸がXかYか不明 | §4.1: 回転ボタンを「取り付け面に戻る」に置換。表示だけを戻し、その後に通常の回転を許可する |

候補を整理しても、局所適合44接触のうち周辺で行き詰まる14接触を隠れて除外しない。
案内例の完成条件と数学上の接着条件は共通化せず、両者を区別する方針を維持した。

初見担当は、自由組立の材料8個が探索を妨げる可能性も指摘した。
材料数を増やす機能を直ちに追加する代わりに、8個を変更可能な試作初期値と明記した。
材料切れで興味や探索が途切れるかは、実際の試用で判断する未解決の評価点である。

## 再確認と残る検証

改訂後、両レビュアーに、自分の指摘が解消したかと、修正に起因する重大・中程度の矛盾がないかの再確認を依頼した。
状態担当は元の2件の解消を確認し、材料・集約後の観察段階を含め追加の修正要求なしと報告した。
通常の追加とUndo後の分岐では履歴の粒度が異なるが、仕様としては成立し、次のUndo対象の表示と試用を重視すべきとの評価だった。
初見担当も元の3件の解消を確認したが、説明面と回転軸の食い違いを追加で指摘したため、上表の対応を施した。
その箇所の追加確認で、初見担当は表示復帰と回転の分離、状態の保持、受け入れ条件への反映を確認し、追加修正なしと報告した。
両者の再確認は担当した指摘と変更箇所に限られ、仕様全体の正しさや使いやすさを保証するものではない。

修正・再確認後の仕様書のSHA-256:

```text
787a4675b419ddb36900cbe6e15ce99433f18d195f2acaf09eded71ab382d49e
```

このハッシュは仕様レビュー完了時のもの。その後、仕様の冒頭に[試作](assembly/README.md)への導線と実装状態を追記した。
今回の独立レビューは試作コードを対象としていない。

静的な確認は、Markdownの読み取り、ローカル参照の存在、コードブロックの対応、末尾空白を対象とする。
状態遷移は仕様上のシナリオとして追ったもので、実行可能なUIのテストではない。
研究上の証明、凍結済みの形状、公開済みビューアーは変更していない。

実装後は仕様書§9の受け入れ条件を確認し、最初の数分のプレイヤー試用を行う。
特に候補一覧の探しやすさ、比較窓と操作の対応、閲覧から戻る動線、材料数の制約は、
文章だけでは評価を完了できない。独立AIレビューを、プレイヤーUXの実証として扱わない。
